# Agent guidance — QMS_controls vault

This is a controlled document system and the counterpart of QMS_demo. Files are the source of truth; edit them directly. Read `lessons-learned.md` and `DEVELOPMENT.md` before extending the build.

## Scope

- Publish **every folder except `guides/`**. `site/.vitepress/publish-scope.mjs` is the single source of truth; `config.mts`, `build-sidebar.mjs` and `wikilinks.mjs` import it.
- This repo must stay independent of `qms-demo`: never import code from it or share a working tree. Configuration is deliberately copied, and each repo evolves on its own.
- Links to guide notes resolve through `site/.vitepress/remote-manifest.json` to `https://jetra360.github.io/qms-demo/`, opening in a new tab. Keep that manifest current when guide filenames change.

## Website rules

- Never alias the `vue` package in `site/.vitepress/config.mts`. It creates two Vue instances and kills hydration. `node_modules` at the vault root is a generated symlink from `docs:prepare`.
- Never write literal double-curly-brace expressions or angle-bracket placeholders in Markdown prose — VitePress/Vue will parse them and fail the build.
- `sidebar.json` is generated by `build-sidebar.mjs`; never hand-edit it. This site uses flat folder groups, not the numeric chapter tree from QMS_demo.
- Mermaid source is carried in a base64 `data-source` attribute (`mermaid.mjs` + `theme/MermaidMount.vue`). VitePress collapses literal newlines in raw HTML. Never style an unrendered `.mermaid` container as a card.
- The sidebar hide control uses `nav-bar-content-before`. `nav-bar-title-after` is inside the title anchor and would navigate home on click.
- After any site change, run `npm run docs:build` and test the sidebar, theme switch, diagram overlays and a cross-site link in a browser.

## Taxonomy first

Read `types/` before creating anything. Valid type values are the H1 headings of notes with `type: Type`:

`Policy`, `SOP`, `WorkInstruction`, `Record`, `AuditFinding`, `CAPA`, `Register`, `Person`, `Role`, `Note`

Never invent a type. If nothing fits, drop an untyped note into `inbox/`.

## Field contract

Use only the canonical fields: `type`, `status`, `tags`, `doc_id`, `revision`, `effective`, `review_due`, `due`, `owner`, `approver`, `severity`, `captured_on`, `performed_on`, `verified_by`, `closed_on`, `implements`, `related_to`, `_organized`. Do not use retired aliases (`id`, `effective_date`, `standard`, `standard_ref`, `process_area`, `supersedes`, `source`, `related_sop`, `related_policy`, `related_finding`, `related_capa`, `has`). Put narrative detail in the body.

Type values are Title Case. Status values are lower case: `active`, `draft`, `under_review`, `open`, `closed`, `obsolete`, `template`.

## File naming

- Content notes: filename = `doc_id` (e.g. `SOP-QA-001.md`); the H1 is the human-readable title.
- Spreadsheet notes: `NAME.sheet.md` with `_display: sheet` and a CSV-like body.
- Saved views: `views/NAME.yml`.
- Person / Role notes: lowercase kebab-case filenames so wikilinks resolve by filename.

## Identity and versioning

- `doc_id` is permanent identity: never reuse, renumber or rename it. Allocate a new ID from `registers/document-master.sheet.md`.
- A new edition keeps the file and increments `revision`; it does not get a new `doc_id`. Set `effective` to the approval date and append to the body's *Revision history*.
- The master sheet is an index only; `python3 scripts/validate-vault.py` checks for drift.

## Linking

Use wikilinks in body and frontmatter. Use one relationship field, `related_to`, except the policy link, which keeps `implements`. `related_to` is a Tolaria default and gets inverse backlinks.

Never write a bare ISO clause reference such as `ISO 9001:2015 §8.7` — make it a wikilink to the matching note in `iso-9001/`, keeping the visible text as the alias. Do not reproduce normative standard text.

## Nonconformance capture (SOP-QA-002 step 2)

- Capture into `inbox/NC-YYYY-MM-DD-NNN.md` with `captured_on` and `tags: [nonconformance, untriaged]`; reporter, product, batch and containment in the body. No `type`, no `_organized`.
- Triage sets `type: AuditFinding`, `doc_id: NC-…`, `severity`, `owner`, `due`, `status: open`, `_organized: true`, swaps `untriaged` for `triaged`, adds `operator`, and moves the note to `audits/`.

## Safety rules

1. An agent may capture into `inbox/` (no type, no `_organized` flag).
2. An agent may create or edit notes with `status: draft` or `status: under_review`.
3. **Only a human may set `status: active`.**
4. Never edit `closed_on` or `verified_by` on a CAPA — closure is a human attestation.
5. Prefix commits that contain agent-written files with `chore(ai):`.
6. Agent-written notes stay `status: draft` until a human promotes them.

## Spreadsheet edits

Preserve `---` frontmatter, `_display: sheet` and the `_sheet` block. Edit only the CSV body. Quote cells containing commas, quotes or line breaks. Never convert a formula into its calculated value.
